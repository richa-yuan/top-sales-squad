# 需求诊断提问库

> 用法：每次提问前先想清楚"**这句话我想拿到什么信息**"。拿不到信息的问题不要问，问了浪费信任。

---

## 第一场会：破冰与摸底（20–30 分钟）

**目标**：拿到场景、拿到数字、拿到人。不推销任何东西。

| 问题 | 想拿到的信息 |
|---|---|
| "你们现在这块是怎么做的？这一步谁在做？" | 现状流程与执行人 |
| "多久做一次？一次多长时间？" | 频次与工时 |
| "做错的时候会发生什么？上一次是什么时候？" | 错误代价与感知度 |
| "这个环节现在是你们最头疼的吗？最头疼的是什么？" | 客户的真实痛点排序 |
| "你们之前试过解决吗？为什么没解决？" | 已有尝试与失败原因 |
| "这个问题现在谁最在意？" | 内部推动人 |
| "你们打算什么时候解决它？" | 时间窗口与紧迫性 |

**结束动作**：约下一场见谁、什么时候、准备什么。

---

## 量化追问（把"很贵"变成数字）

| 客户说 | 你问 |
|---|---|
| "人工成本很高" | "这块一年大概投入多少人？每个多少工时？时薪大概多少？" |
| "经常出错" | "一年大概出多少次？每次的代价是返工还是客诉？客诉一次赔多少？" |
| "效率太低了" | "现在处理一笔要多久？行业好的水平是多久？差的这段时间卡在下游谁身上？" |
| "预算不够" | "这个数字跟你们什么支出比？占年度 IT/设备预算百分之多少？" |
| "很多客户投诉" | "投诉率大概多少？主要集中在哪类？处理一次占多少人力？" |
| "停机损失大" | "一年停几次？每次几小时？这条线一小时产值多少？" |

## 需求真实性验证（判断是不是伪需求）

| 问题 | 想拿到的信息 |
|---|---|
| "如果这周五这个问题必须解决，你会怎么做？" | 有没有替代方案绕过你 |
| "这个问题去年就有人提过吗？为什么现在要做？" | 触发事件与紧迫性真伪 |
| "你们老板最近提过什么关于这块的要求？" | 高层真实关注点 |
| "如果这个问题半年后自动消失了，你会松一口气还是无所谓？" | 问题的真实痛感 |
| "这个项目如果做成了，谁会第一个受益？" | 内部受益者 |
| "如果做不成会怎样？" | 风险与紧迫度 |
| "你们有没有试过自己做？" | 自建 vs 采购的判断 |

**红旗信号**：客户说不出具体数字、说不出受益人、说不出触发事件、答"领导让做"但说不出领导在意什么 → 这多半是一个**被指派的伪需求**，重点转向找出真正的驱动力。

## 决策链探询

| 问题 | 想拿到的信息 |
|---|---|
| "这种事在你们那边一般怎么定？谁拍板？" | 决策流程与拍板人 |
| "流程一般走多久？卡在哪个环节？" | 流程时长与瓶颈 |
| "有固定的模板或参数要求吗？" | 采购合规约束 |
| "除了您，还有谁会参与？他们的标准是什么？" | 其他决策者与标准 |
| "以前类似的采购是怎么走的？" | 历史路径（照着走） |
| "预算在哪个科目？今年还有多少空间？" | 预算来源与额度 |
| "什么情况这单会被否掉？" | 否决触发条件（最有价值的问题） |

---

## 竞争与内部替代

| 问题 | 想拿到的信息 |
|---|---|
| "目前这类需求还有别的方案在谈吗？" | 竞争态势 |
| "有没有内部团队在做这块？" | 内部替代方案（AI 单子必问） |
| "如果方案一样，你们一般按什么挑？" | 客户的真实决策标准 |
| "上次类似采购最后选了谁？为什么？" | 历史采购逻辑（非常可靠） |

---

## 推进承诺（每次会都要带走一个动作）

收尾必须问出明确的下一步：

- "下一步我做什么最有价值？"
- "我下一步要见的是谁？什么时候方便？"
- "还需要我准备什么材料？给谁看？"
- "有什么会阻碍这件事推进？"（**直接问反对者**）
- "我们 XX 前完成 XX，您看行吗？"（给具体时间点）

---

## 提问纪律

1. **一次只问一件事**，问完等回答，别连环追问
2. **先问事实，再问感受**（"一年多少次"→"最烦的是哪部分"）
3. **沉默是工具**，问完停 3 秒，让对方自己往下说
4. **客户跑题就跟着跑**，那是他在告诉你真正的痛点
5. **不要在第一场会讲方案**，讲了就丢掉提问权
6. **复述确认**："我理解一下，您的意思是……对吗？"——这既是尊重，也是防误解
