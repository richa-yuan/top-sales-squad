# 异议处理话术库

## 通用拆解法：四层拆解

任何异议，先拆成四层，再对症下药。跳过前三层直接给话术，等于猜谜。

| 层 | 追问 | 意义 |
|---|---|---|
| **字面诉求** | 他嘴上说了什么？ | 明确要处理的对象 |
| **真实顾虑** | 他真正怕什么？（风险 / 超预算 / 丢面子 / 内部政治 / 没人会用 / 换了挨骂） | 决定话术方向 |
| **缺失证据** | 我缺什么证据才能证明他担心的不会发生？ | 决定要准备什么 |
| **决策风险** | 我不解决会怎样？多久解决不了会怎样？ | 决定推进节奏与紧迫感 |

**核心原则**：客户说的和客户想的，通常不是一回事。他嘴上说"太贵"，真实顾虑往往是"我无法证明这笔钱花得值 / 我要为这个决定负责"。

## 六大高频异议

### 1. 价格太高 / 太贵了

**真实顾虑**：没有价值锚点；比预算贵；怕回去被财务问；怕自己被问责。

**应对结构**（先拆再接）：
1. **先认同，不辩解**："这个价格在您这个体量的预算里确实是笔大开销，我不绕这个。"
2. **把价格换算成他熟悉的口径**："我们换个算法——这套东西一年帮您省下 XX 人日，按您这边人力成本折算大概是 XX 万，比价差是 XX 倍。"
3. **拆价格构成**："这个价里 XX% 是软件本身，XX% 是实施和一年服务，XX% 是我们承担的风险。如果只看软件那部分，比 XX 家便宜。"
4. **给三档，让他在档位间选而不是在"买/不买"间选**：入门 / 标准 / 旗舰。
5. **让价换条件**（他坚持压价时）："如果首年预付、签两年、把验收指标写进合同，我可以申请这个价。但服务期和范围要相应调整。"

**必须准备的事实**：他自己的成本基线数字、同类方案价格带、三档方案的具体差异。

**失败退路**：如果他确实超预算，**缩小范围**而不是降价——"我们做一个更小的范围，先解决 XX 环节，跑通了再扩。"这比降价更能保住长期价格体系。

**常见错误**：立刻打折。降价一旦成为第一次让步，后面就没有终点。

---

### 2. 我们已经在用 XX 了 / 有免费替代品

**真实顾虑**：切换成本、迁移风险、内部已有投入、决策者不愿推翻自己。

**应对结构**：
1. **不否定他的现有方案**："XX 在你们那个环节确实做得挺稳，这个我们不否认。"
2. **找边界**：他们方案解决不了的边界在哪？"我更想知道——XX 在遇到 XX 情况时是怎么处理的？"
3. **把对比变成维度对比，不是价格对比**：列一张表（复杂场景准确率 / 长尾覆盖 / 私有化 / 定制响应 / 与现有系统集成 / 迁移成本 / 三年 TCO）
4. **给共存方案**：能否做补充而非替代？"有没有可能先在 XX 环节补一段，验证了再谈整体替换？"——这一步往往能直接启动 POC。
5. **算迁移成本**："替换成本我给你算清楚：数据迁移 XX 人日、停机窗口 XX 小时、并行运行 XX 周。这些我方承担还是你方承担，写进合同。"

**必须准备的事实**：竞品的实际能力边界（公开文档、客户反馈）、你自己的迁移方案与成本。

**失败退路**：共存试点，用一个场景证明增量价值。

---

### 3. 预算不够 / 明年再说

**真实顾虑**：可能不是真没钱，而是优先级不够、没找到预算科目、或者他不是决策人。

**应对结构**：
1. **问预算来源**："如果是钱的问题，我们看看能不能挪到别的科目——您这边 XX 这个预算今年还有多少空间？"
2. **问优先级**："如果今年只能做一件事，您觉得哪件事最该先解决？为什么它排在第一位？"
3. **做小切口**："我们能不能先做一个 XX 万的试点，用的是现有资源，不占新增预算——跑通了再走正式流程。"
4. **制造时间锚点**："明年预算是 Q3 立项，倒推的话，Q1 至少要完成 POC 和参数确认，不然赶不上。"
5. **落一个明确的最小承诺**："那我们今天定一件事：下周三之前我们出一版 POC 方案，您这边确认能不能配合出人。这样可以吗？"

**必须准备的事实**：客户的预算周期与立项节点。

**失败退路**：拿到"再想想"的承诺，转成低成本的持续动作（每月技术交流、行业材料、试点）。

---

### 4. 我需要先问领导 / 我们要开会讨论

**真实顾虑**：可能真要汇报，也可能他在推你、拖延你。

**应对结构**：
1. **要具体**：不是"我帮你准备材料"，而是"您打算怎么汇报？我按您的汇报逻辑来做一份摘要，您 10 分钟能讲完。"
2. **摸决策标准**："领导最看重哪三点？我们把这三点放在最前面。"
3. **争取列席**："下次会我能不能一起讲十分钟？我把技术细节都准备好，您只要讲价值那部分。"
4. **留一个可验证的东西**：哪怕会议不通过，也可以带走一个免费诊断报告、一份 ROI 测算——"如果这次没定，我出一份你们内部的测算稿，下次讨论直接用。"

**必须准备的事实**：汇报对象的关注点、可能的反对者。

**失败退路**：拿到会议时间点 + 参会人名单。

---

### 5. 能不能再便宜点 / 给个折扣

**真实顾虑**：谈判习惯、预算上限、还有别的候选在压价、或者他真觉得值这个数。

**应对结构**：
1. **问清是哪种价**："您说的便宜，是首年价、还是三年总价？我按您关心的口径来算。"
2. **用交换换价格**（把降价做成交易）：
   - 预付比例 ↑ → 折扣
   - 合同期 ↑ → 折扣
   - 案例授权/推荐语 → 折扣
   - 采购范围 ↑ → 折扣
   - 付款方式从账期改预付 → 折扣
3. **给"底价"并附条件**："这是我能做到的价格，条件是三个月内付清、签两年。"
4. **不降价改方案**："价格我确实动不了，但我可以把 XX 模块加进去，价值更高而你的预算没变。"

**必须准备的事实**：底价、折扣授权梯度（谁能批多少）、换条件的优先级。

**失败退路**：明确告知"这个价格是我的权限极限"，比无限拉扯更快结束战斗。

---

### 6. 再看看 / 我们有别的选择

**真实顾虑**：信息不足、风险感、有人在内部反对、或者你的方案不是最优解。

**应对结构**：
1. **问具体在比什么**："您说的别的选择，主要是比价格、比功能，还是比我们更放心？"
2. **补他缺的信息**：技术细节、案例、SLA、实施团队、售后网络——"再看看"往往是"还不敢下决心"
3. **降低他的决策成本**：给一个最小决策单位——先做一个环节、一个季度、一个 POC。
4. **设一个温和的时间锚点**："我理解您要谨慎。那我们定个时间——下个月中旬我做一次完整汇报，您看完如果还是不行，我们就不继续折腾您。"
5. **问"如果我解决掉 X，您这边有顾虑吗"**：把决策变成条件式。

**必须准备的事实**：差异化证据包（案例、指标、SLA）。

**失败退路**：定期低打扰触达（每月一次带新信息），不逼单。

## 谈判底线纪律

1. **不先出价**，除非客户明确要求先看报价——先出价等于把锚定权交出去
2. **每次让步都要换回东西**，并**明说**："这一条我可以给，前提是……"
3. **让步幅度递减**：第一次给大头，后面越来越小（10% → 5% → 2%），传递"到底了"的信号
4. **不在压力下当场决定**："这个我需要回去核一下成本，明天给你答复。"当场答应是最大的让步
5. **情绪客户不打价格战**：他情绪化的时候，你越冷静越有利
